# Enterprise requirements management and ALM tools: broad scan for requimd

Scan date: November 2026. Sources are public web pages found by search on that date. Most of them are vendor pages, so claims about features are the vendors' own claims unless marked otherwise. Where only older material was found, the date is given. Notes marked "background, not re-verified" come from general domain knowledge and were not confirmed by a source in this scan. The report writer should treat them as hypotheses.

## Q1: What does each tool offer? (uniform profiles)

### Takeaway
All ten tools are server or cloud databases of typed items with attributes, typed links, baselines and reviews. They differ mainly in configuration management (IBM, Polarion, Codebeamer), the review experience (Jama, Modern Requirements), document-style authoring (Polarion LiveDoc, ReqView, Modern Requirements Smart Docs) and how much they invest in built-in text-quality checking (Jama Advisor, Visure, Innoslate, IBM RQA, Polarion Copilot). ReqView is the only one in the set that stores projects as files in git, which makes it the closest relative of requimd.

### Cited Findings

#### 1. IBM Engineering Requirements Management DOORS Next (and classic DOORS 9.7)
- **Vendor/licence:** IBM, part of the Engineering Lifecycle Management (ELM) suite. Commercial, with a public pricing page for SaaS and on-premises offerings — [IBM pricing](https://www.ibm.com/products/requirements-management/pricing). Classic DOORS 9.7.x is still supported "beyond the typical three year period", and IBM promises at least 12 months' notice before end of support (the page was updated 16 February 2026) — [IBM lifecycle via search](https://www.ibm.com/support/pages/node/7234700).
- **Storage/data model:** A server database (Jazz). Artifacts are organised in modules, components and streams. DOORS Next sets baselines per component or project, while classic DOORS sets them per module and groups them in "baseline sets"; a pure::variants add-on adds module-level baselines to DOORS Next — [IBM community blog 2024](https://community.ibm.com/community/user/blogs/tom-hollowell/2024/08/09/embracing-the-evolution-module-baselines-in-ibm-do).
- **Configuration management:** Streams, baselines and change sets. Global configurations combine the configurations of several lifecycle tools (requirements, tests, models) and can be nested. A global baseline automatically creates baselines of the local streams. Once configuration management is enabled for a project it cannot be disabled, and global configurations need their own GCM application server — [IBM docs: Overview of Global Configurations](https://www.ibm.com/docs/SSYMRC_7.0.3/com.ibm.rational.gcapp.doc/topics/c_overview_gcapp.html), [IBM docs: change sets in personal streams](https://www.ibm.com/docs/en/SSYMRC_7.2/com.ibm.rational.gcapp.doc/topics/t_work_with_multiple_csets.html), [Jazz.net CLM configuration management](https://jazz.net/library/article/1492), [Sodius Willert: change sets with configurations](https://www.sodiuswillert.com/en/blog/recommendations-on-using-changes-with-configurations-in-doors-next), [Sodius Willert: baseline best practices](https://www.sodiuswillert.com/en/blog/best-practices-for-managing-baselines-with-ibm-doors-next).
- **Pain point with configuration management:** A user on the Jazz forum asked for a "graphical history/branch view for streams/baselines ... like git", which suggests the branching model is hard to see — [Jazz forum](https://jazz.net/forum/questions/291047/feature-request-graphical-historybranch-view-for-streams-baselines-in-doors-next-global-configuration-like-git).
- **Text quality and AI:** IBM Engineering Requirements Quality Assistant (RQA) scores requirements in DOORS Next and DOORS 9 "based on criteria consistent with the INCOSE Guide for Writing Requirements", using Watson NLP — [IBM RQA product page](https://www.ibm.com/products/requirements-quality-assistant), [IBM RQA architecture](https://www.ibm.com/docs/SS3UPN/com.ibm.help.rm.assist.doc/topics/c_rqa_architecture.html). A reseller reports that the RQA SaaS service was discontinued and replaced by a comparable service — [Requisis](https://requisis.com/en/saas-doors-dng/rqa-saas.html). IBM Engineering AI Hub brings "task-level" AI agents into ELM tools including DOORS Next — [TechFinitive](https://www.techfinitive.com/ibm-to-launch-task-level-ai-agents-for-engineers/), [IBM community Dec 2025](https://community.ibm.com/community/user/blogs/bhawana-gupta/2025/12/16/driving-engineering-excellence-new-releases-and-ai), [Requirements AI assistant for DOORS Next, Feb 2025](https://community.ibm.com/community/user/blogs/daniel-moul/2025/02/13/requirements-ai-assistant-for-doors-next).
- **Classic DOORS scripting:** DXL is the scripting and trigger language of classic DOORS; DOORS Next does not support DXL — [IBM 9.7.0.1 notes via search](https://www.ibm.com/support/pages/node/593607), [Jazz forum via search](https://jazz.net/forum/questions/263820/doors-classic-96-how-to-add-an-existing-module-baseline-to-a-baseline-set).
- **Distinctive ideas:** (1) Configuration management that spans several tools (global configuration). (2) Change sets as a reviewable unit of edits. (3) Baseline sets: a named set of per-module baselines. (4) A quality score per requirement aligned to the INCOSE guide.

#### 2. Jama Connect (Jama Software)
- **Vendor/licence:** Jama Software, commercial SaaS or self-hosted. There are licence types for creators, reviewers and stakeholders. A reviewer licence lets a user take part in reviews, approve and comment, but not start reviews or open items in the core project. Anyone invited to a review automatically gets a reviewer licence. Jama's pricing page says reviewer licences are included at no extra charge — [Jama help: license types](https://help.jamasoftware.com/en/reference/permissions/license-types-26811.html), [Jama help: glossary](https://help.jamasoftware.com/ah/en/reference/glossary.html), [Jama pricing (legacy page)](https://www.jamasoftware.com/legacy/platform/pricing/).
- **External reviewers:** @mentioning an email address that has no account creates a temporary account; after 30 days the licence expires unless it is made permanent — [Jama help: add a reviewer from outside Jama Connect](https://help.jamasoftware.com/ah/en/collaborating-with-your-team/stream---staying-connected/comments/add-a-reviewer-from-outside-jama-connect.html).
- **Review Center:** Iterative, collaborative review of requirements and tests, with electronic signature roles, review activity history for audits, and an option to block deletion of reviews that carry e-signatures (added in 2019) — [Jama blog 2019](https://www.jamasoftware.com/blog/introducing-new-and-improved-jama-connect-review-center), [Jama press release](https://www.jamasoftware.com/company/press/updates-to-jama-connect-review-center/). Under 21 CFR Part 11, a review is the electronic record; a signature records the signer's name, the time and the meaning of the signature, and once any approver has signed a version, the review cannot be deleted through the user interface — [Jama Part 11 white paper, Dec 2023](https://www.jamasoftware.com/media/2023/12/jama-connect-and-fda-21-cfr-part-11.pdf).
- **Traceability:** "Live Traceability" is marketed as real-time visibility across development. A third-party roundup describes "Trace Scores" as a continuously measured coverage metric — [TechFundingNews 2026](https://techfundingnews.com/9-best-traceability-software-platforms-for-engineering-teams-in-2026/), [Jama webinar](https://www.jamasoftware.com/legacy/webinar/live-traceability-the-golden-key-to-proof-of-compliance/).
- **Text quality and AI:** Jama Connect Advisor scores requirement text against INCOSE rules and/or EARS notation, chosen by the user. Results come in two sections (INCOSE rules analysis with colour-coded alignment and per-rule suggestions; EARS notation analysis with syntax guidance). Recommendations appear while the user writes, and reports can be downloaded to track quality over time — [Jama help: interpreting the results](https://help2.jamasoftware.com/ah/en/jama-connect-advisor-/interpreting-the-results.html), [Jama blog Mar 2025](https://www.jamasoftware.com/blog/2025/03/20/utilize-artificial-intelligence-and-natural-language-processing-to-produce-high-quality-requirements-with-jama-connect-advisor/), [Jama AI blog](https://www.jamasoftware.com/blog/ai-requirements-management/).
- **User view:** A G2 reviewer named live traceability and Review Center as their favourite features — [G2 Jama reviews](https://www.g2.com/products/jama-connect/reviews).
- **Distinctive ideas:** (1) A free reviewer role restricted to one review. (2) A review as a versioned object with e-signatures. (3) A trace score as a single coverage number. (4) A rule-by-rule quality report (INCOSE plus EARS) shown while writing.

#### 3. Siemens Polarion ALM / Polarion REQUIREMENTS
- **Vendor/licence:** Siemens Digital Industries Software, commercial; on-premises and "Polarion X" SaaS — [Polarion X 2512 blog](https://blogs.sw.siemens.com/polarion/polarion-x-2512-whats-new-and-noteworthy/). Releases are named by year and month (2310, 2404, 2410, 2506, 2512, 2606) — [Polarion blog](https://blogs.sw.siemens.com/polarion/polarion-alm-2606-whats-new-and-noteworthy/).
- **Storage/data model:** Work items (typed, with custom fields and link roles) shown inside LiveDoc documents, which read like Word documents but each paragraph can be a work item. (Polarion stores its data in a Subversion repository — background, not re-verified.)
- **Branching and variants:** 2310 added bulk branching or copying of several documents at once while keeping relative links, and an integration with Teamcenter Product Configurator that derives "100%" specifications from "150%" LiveDocs — [Polarion 2310](https://blogs.sw.siemens.com/polarion/polarion-alm-2310-whats-new-and-noteworthy/). 2404 added automatic merge between branched and master documents — [Polarion 2404](https://blogs.sw.siemens.com/polarion/polarion-alm-2404-whats-new-and-noteworthy/). In 2512, merges also carry work item links; Collections give baseline-scoped views; OSLC links can point to a specific work item revision — [Polarion 2512, 3 Dec 2025](https://blogs.sw.siemens.com/polarion/polarion-alm-2512-whats-new-and-noteworthy/).
- **Review/approval:** Work item approval and signatures; 2512 notifies users automatically, with direct links, when their signature is required and when others sign or decline. 2512 also added @mentions in documents with email notification — [Polarion 2512](https://blogs.sw.siemens.com/polarion/polarion-alm-2512-whats-new-and-noteworthy/), [Polarion 2512 feature matrix](https://polarion.plm.automation.siemens.com/hubfs/Polarion%202512%20Feature%20Matrix%20(1).pdf).
- **Interchange:** ReqIF import and export (2512: several documents into one ReqIF file, re-export of existing ReqIF files); connectors for DOORS, Jira (rich text and mentions sync both ways), Azure DevOps and HP ALM; REST API extended — [Polarion 2512](https://blogs.sw.siemens.com/polarion/polarion-alm-2512-whats-new-and-noteworthy/).
- **AI:** Polarion Copilot (2512, paid add-on) has three tools: Similarity Analysis (finds semantically similar work items, i.e. duplicates), Consistency Check (follows links by role and depth to flag contradictions), and Content Validation (checks requirement descriptions against INCOSE rules and suggests fixes). 2606 added a Copilot API for customisations — [Polarion 2512](https://blogs.sw.siemens.com/polarion/polarion-alm-2512-whats-new-and-noteworthy/), [Polarion 2606](https://blogs.sw.siemens.com/polarion/polarion-alm-2606-whats-new-and-noteworthy/), [Siemens on LLMs in Polarion](https://blogs.sw.siemens.com/polarion/reasons-and-use-cases-of-integrating-large-language-models-into-polarion/).
- **Distinctive ideas:** (1) A document is the editing surface and the item store at once (LiveDoc). (2) Branch a document, then merge it back with links intact. (3) 150 %/100 % variant specifications. (4) Consistency check that follows links to find contradictions.

#### 4. PTC Codebeamer
- **Vendor/licence:** PTC, commercial, sold together with pure::variants (product line engineering). Codebeamer 3.0 launched in 2025 — [PTC news 2025](https://www.ptc.com/en/news/2025/ptc-launches-codebeamer-3). Codebeamer 3.2, Codebeamer AI 1.0 and pure::variants 7.2 were announced on 15 January 2026; Codebeamer 3.3 with Codebeamer AI 1.2 followed later in 2026 — [PTC news 2026](https://www.ptc.com/de/news/2026/ptc-delivers-new-ai-functionality-with-new-alm-releases), [CIMdata summary](https://www.cimdata.com/en/industry-summary-articles/item/29186-ptc-delivers-new-ai-functionality-for-software-driven-product-development-with-new-alm-releases), [PTC community: 3.3 released](https://community.ptc.com/codebeamer-445/codebeamer-3-3-has-released-175154).
- **Variants:** The feature-based product line engineering module creates streams automatically and uses "Delta Merge" (beta) for variant development and reuse, so teams can work at platform and variant level. 3.3 adds configuration-aware product line engineering with pure::variants — [engineering.com](https://www.engineering.com/ptc-updates-alm-portfolio-with-codebeamer-and-pure-variants/), [PTC blog 3.1](https://www.ptc.com/en/blogs/alm/product-release-codebeamer-3-1-pure-variants-7-1).
- **Review Hub:** Bulk approval and rejection, clearer notifications, visual highlighting of differences (3.2); clearer separation of moderator and reviewer roles (3.3). A claim that this cuts review cycle times by up to 30 % could not be verified in PTC's own material — [all-about-industries](https://www.all-about-industries.com/three-new-solutions-for-application-lifecycle-management-a-7d41a91d9b715a004d6c28b84c317bb1/), [industrialnews](https://industrialnews.co.uk/ptc-enhances-ai-features-in-alm-portfolio/), [SPK roadmap explainer](https://www.spkaa.com/blog/the-codebeamer-product-roadmap-2025-explained).
- **Distinctive ideas:** (1) Variants as feature-driven streams with delta merge. (2) A review shown as a diff against the last reviewed version. (3) Separate moderator and reviewer roles.

#### 5. Visure Requirements ALM
- **Vendor/licence:** Visure Solutions, commercial — [Visure ALM page](https://visuresolutions.com/free-trial/alm).
- **Text quality and AI:** A "Quality Analyzer" checks requirement quality while the user writes, flagging ambiguity; Visure's own blog says AI analyzers can assess against INCOSE guidelines and EARS, but no list of the rules Visure actually implements was found — [Visure AI requirements](https://visuresolutions.com/features/ai-requirements-management/).
- **Interchange:** ReqIF is listed among native integrations, with examples of exchange with Cameo Systems Modeler and Capella via ReqIF — [Visure ALM page](https://visuresolutions.com/free-trial/alm), [Visure vs Innoslate (vendor comparison)](https://visuresolutions.com/compare/innoslate-mbse-software-vs-visure-requirements).
- **Distinctive ideas:** (1) Quality checks while writing, positioned as the core feature. (2) ReqIF round trip with MBSE tools.

#### 6. ReqView (Eccam)
- **Storage/data model:** Projects are files (a .reqw file or a project folder with project.json), which can be kept in Git or SVN. Documents hold objects with custom attributes and typed links. History is tracked inside the project when "Save History" is on — [ReqView docs: change management](https://reqview-homepage.netlify.app/doc/change-management).
- **Git workflow:** ReqView 2.19 (April 2024) added Git integration. Users edit a document after locking its file in the Git repository and then commit to the remote; locks are kept in `.git/refs/reqview/*`. Git LFS is recommended for attachments — [ReqView 2.19 release](https://reqview-homepage.netlify.app/blog/2024-04-19-release-2.19.0), [ReqView docs: Git collaboration](https://reqview-homepage.netlify.app/doc/git-collaboration), [ReqView docs: Git administration](https://reqview-homepage.netlify.app/doc/git-administration).
- **Suspect links:** Turned on per link type (`suspect` property). A link becomes suspect when chosen attributes of the target change (heading, text, deleted, attachments or custom attributes). Flags can be filtered and cleared per link, per selection or for the whole project. Suspect links depend on the stored history — [ReqView docs: change management](https://reqview-homepage.netlify.app/doc/change-management), [ReqView suspect links beta, 2017](https://reqview-homepage.netlify.app/blog/2017-02-07-beta-suspect-links).
- **Review:** A Discussion pane with comments that can be resolved and reopened (deleted comments stay in history), plus a convention of a custom `status` attribute (Draft, Ready, Reviewed, Approved, Released) and filters for each stage and for unresolved comments — [ReqView docs: change management](https://reqview-homepage.netlify.app/doc/change-management).
- **Baselines/comparison:** Compare the current project with a baseline project file or folder, side by side ("Theirs"/"Mine"), with a "Diff Theirs to Base" mode; project history can be exported as an HTML report — [ReqView docs: change management](https://reqview-homepage.netlify.app/doc/change-management).
- **Reuse:** Linked projects (beta 2.15) allow links across projects — [ReqView linked projects](https://reqview-homepage.netlify.app/doc/linked-projects).
- **Reporting:** Traceability matrix and reports exported to DOCX, XLSX, PDF, CSV or custom templates — [ReqView docs: change management](https://reqview-homepage.netlify.app/doc/change-management).
- **Distinctive ideas:** (1) Choose per link type which attributes make a link suspect. (2) Clearing suspect flags in bulk. (3) Three-way comparison with a base. (4) Status values as a lightweight approval workflow.

#### 7. SPEC Innovations Innoslate
- **Vendor/licence:** SPEC Innovations, commercial, cloud or on-premises; combines requirements with MBSE — [Innoslate product page](https://specinnovations.com/innoslate), [MBSE software](https://specinnovations.com/innoslate/model-based-systems-engineering-software).
- **Text quality:** A requirements quality checker based on NLP gives each requirement a quality score in real time and flags ambiguity, incompleteness and redundancy; the vendor also names clarity, completeness, consistency and verifiability. It has existed since at least 2018 — [Innoslate NLP quality analytics](https://specinnovations.com/innoslate/nlp-quality-analytics), [SPEC blog on clear requirements](https://specinnovations.com/blog/how-to-ensure-requirements-are-clear-and-unambiguous), [NDIA 2018 vendor briefing](https://ndia.dtic.mil/wp-content/uploads/2018/systems/Thurs_ToolVendor_Dam.pdf), [webinar: INCOSE guide and AI quality checker](https://specinnovations.com/blog/meet-incoses-guide-to-writing-requirements-with-ai-quality-checker-webinar).
- **AI:** Requirements AI, Test Case AI, Translate AI, Risk AI, Summarize AI and Text Prompts AI; generative AI through Ask Sage for controlled data handling — [SPEC AI flyer](https://specinnovations.com/hubfs/AI%20Flyer.pdf), [AI in MBSE use cases](https://specinnovations.com/hubfs/AI%20in%20MBSE%20Use%20Cases.pdf).
- **Impact analysis:** A February 2026 update added impact analysis enhancements — [BusinessWire, 4 Feb 2026](https://www.businesswire.com/news/home/20260204376357/en).
- **Distinctive ideas:** (1) Quality score per requirement with a shareable quality report. (2) Requirements and system models in one database (design level). (3) AI translation of requirements.

#### 8. Modern Requirements4DevOps (Azure DevOps)
- **Vendor/licence:** Modern Requirements, commercial add-on that runs inside Microsoft Azure DevOps; requirements are Azure DevOps work items — [product page](https://modernrequirements.com/products/modern-requirements4devops).
- **Smart Docs:** A Word-like editor for structured documents built from work items; from a document users can compare with a saved version, clone across projects, capture a baseline, or send it for review — [Smart Docs](https://www.modernrequirements.com/products/modern-requirements4devops-features/smart-docs/).
- **Review:** A Review button in any baseline, Smart Doc or version package opens a pre-filled review request. Approval moves the work item to a defined post-approval state; approvals and rejections carry mandatory audit trails; an approval audit report is produced when the review closes; a baseline can be created from the reviewed set in one step — [Review module](https://www.modernrequirements.com/products/modern-requirements4devops-features/review/).
- **AI:** Copilot4DevOps answers plain-language questions about the requirement set (e.g. which requirements lack test coverage, what changed since the last baseline); admins can turn it off — [product page](https://modernrequirements.com/products/modern-requirements4devops).
- **Distinctive ideas:** (1) Review a document or baseline as one package, then baseline exactly what was approved. (2) Approval moves item status automatically. (3) Natural-language queries over coverage and changes since a baseline.

### Inferences
- Classic DOORS is in long-term maintenance; IBM's innovation is in DOORS Next and the AI Hub. Many organisations still run DOORS 9 and exchange data by ReqIF (background, not re-verified).
- AI features in 2025-2026 cluster into three groups: quality scoring against INCOSE/EARS (Jama, IBM, Polarion, Visure, Innoslate), duplicate and contradiction detection (Polarion Copilot), and generating downstream items such as tests (Spira, Innoslate, Jama). The first two groups have rule-based parts that work offline; requimd already covers part of the first.

### Gaps
- Licence prices are not public for most tools (only IBM publishes a pricing page); not researched further.
- Codebeamer's own 3.3 release page returned HTTP 403, so its details come from press summaries.
- For Perforce ALM, SpiraTeam and Visure, no primary documentation on link types, suspect links or coverage reports was fetched in this scan.
- Data model details (Polarion SVN backend, DOORS Next OSLC, Jama REST API) are background knowledge and were not confirmed with a cited source here.
- No independent benchmark of any AI quality checker's accuracy was found.

## Q2: Which capabilities are "table stakes"?

### Takeaway
Every tool in the scan has typed items with IDs and custom attributes, a hierarchy (document or module), typed links with a trace matrix and coverage views, change history, baselines with comparison, comments and review/approval, document export (Word/PDF), and some import/export (ReqIF or CSV/Excel). Suspect links, e-signatures for regulated industries, and an AI quality assistant are now expected in the upper market.

## Q3: Which features are distinctive per tool?

### Takeaway
Distinctive features are: IBM's global configurations across tools; Jama's Review Center with free reviewer licences and Advisor rule-by-rule scoring; Polarion's LiveDoc (document equals item store), document branching with merge, and Copilot consistency checking; Codebeamer's feature-driven variants with delta merge and its diff-based Review Hub; ReqView's file-based projects in git with per-link-type suspect rules; Modern Requirements' "review the package, baseline what was approved"; Valispace's parameters inside requirement text.

### Cited Findings

- The features that matter for requimd are those that do not need a server: rule-by-rule quality reports, consistency checks along links, per-link-type suspect rules, review packages bound to a git ref, document-like output, and typed parameters. ## Q4: How do they handle review and approval by stakeholders who are not tool experts?

### Takeaway
The common pattern is a separate, simplified review surface: a "review" object that packages a set of items or a document at a version, invites people by email, collects comments and approve/reject votes per item, and keeps an audit record (with e-signatures where regulated). Vendors lower the barrier with free or temporary reviewer licences, email notifications with direct links, and difference highlighting so reviewers only read what changed.

### Cited Findings
- Jama: reviewer licences at no extra charge; invitees get a reviewer licence automatically and see only the review; temporary 30-day accounts for outside people via @mention — [Jama license types](https://help.jamasoftware.com/en/reference/permissions/license-types-26811.html), [Jama external reviewer](https://help.jamasoftware.com/ah/en/collaborating-with-your-team/stream---staying-connected/comments/add-a-reviewer-from-outside-jama-connect.html), [Jama pricing](https://www.jamasoftware.com/legacy/platform/pricing/).
- Codebeamer Review Hub: bulk approve/reject, visual difference highlighting, separate moderator and reviewer roles — [all-about-industries](https://www.all-about-industries.com/three-new-solutions-for-application-lifecycle-management-a-7d41a91d9b715a004d6c28b84c317bb1/), [industrialnews](https://industrialnews.co.uk/ptc-enhances-ai-features-in-alm-portfolio/).
- Polarion: automatic notification with direct links when a signature is needed, updates when others sign or decline; @mentions in documents — [Polarion 2512](https://blogs.sw.siemens.com/polarion/polarion-alm-2512-whats-new-and-noteworthy/).
- Modern Requirements: review request launched from a document or baseline, approval moves the item status, audit report at closure — [MR review](https://www.modernrequirements.com/products/modern-requirements4devops-features/review/).
- Perforce ALM: removed the separate review mode so reviewers work inside the document — [Perforce blog](https://www.perforce.com/blog/use-testtrack-more-bugs).
- ReqView: comments with resolve/reopen and a status attribute workflow; no separate reviewer role found — [ReqView docs](https://reqview-homepage.netlify.app/doc/change-management).

### Inferences
- For requimd the review surface could be the static HTML site: a "review package" page for a git range showing only changed items with their diff, plus a way to record approvals as a file in the repository (for example signed commits or a review record file) instead of a server. A pull request on GitHub/GitLab already gives comments and approval, but analysts' stakeholders often cannot use it; a printable or PDF review document is the low-tech fallback.

### Gaps
- No user-review source specifically about how non-expert stakeholders experience these review tools (G2/Capterra pain points were not fetched in detail).

## Q5: Baselines, branching and variants compared with git

### Takeaway
Enterprise tools implement inside their database what git gives for free: snapshots (baselines), branches (streams, branched documents), change sets, and merge. They add things git lacks: cross-tool configurations, per-item version links (OSLC to a revision), and feature-model-driven variants (150 %/100 %). Their users find the branch structure hard to see; one DOORS Next user explicitly asked for a "git-like" graphical history.

### Cited Findings
- DOORS Next: streams, baselines, change sets, global configurations; configuration management cannot be turned off once enabled; a separate GCM server is needed — [IBM docs](https://www.ibm.com/docs/SSYMRC_7.0.3/com.ibm.rational.gcapp.doc/topics/c_overview_gcapp.html), [Jazz.net](https://jazz.net/library/article/1492), [Sodius Willert](https://www.sodiuswillert.com/en/blog/best-practices-for-managing-baselines-with-ibm-doors-next).
- DOORS Next user request for a git-like branch view — [Jazz forum](https://jazz.net/forum/questions/291047/feature-request-graphical-historybranch-view-for-streams-baselines-in-doors-next-global-configuration-like-git).
- Classic DOORS: per-module baselines grouped in baseline sets — [IBM community](https://community.ibm.com/community/user/blogs/tom-hollowell/2024/08/09/embracing-the-evolution-module-baselines-in-ibm-do).
- Polarion: branched documents, automatic merge (2404), merge including links (2512), 150 %/100 % with Teamcenter — [Polarion 2310](https://blogs.sw.siemens.com/polarion/polarion-alm-2310-whats-new-and-noteworthy/), [2404](https://blogs.sw.siemens.com/polarion/polarion-alm-2404-whats-new-and-noteworthy/), [2512](https://blogs.sw.siemens.com/polarion/polarion-alm-2512-whats-new-and-noteworthy/).
- Codebeamer: feature-based product line engineering with automatic streams and delta merge; pure::variants configuration-aware — [engineering.com](https://www.engineering.com/ptc-updates-alm-portfolio-with-codebeamer-and-pure-variants/).
- Spira: baseline bound to a release — [Spira](https://inflectra.com/SpiraTeam/Highlights/Baselining.aspx).
- ReqView: uses git itself, with file locks because its JSON files do not merge well; also its own internal history (needed for suspect links) — [ReqView Git collaboration](https://reqview-homepage.netlify.app/doc/git-collaboration), [ReqView change management](https://reqview-homepage.netlify.app/doc/change-management).

### Inferences
- Plain Markdown in git (requimd) merges line by line, so it avoids ReqView's need for locks. requimd's lock file already plays the role of ReqView's internal history for suspect links.
- What git does not provide and analysts expect: a named baseline with a description and an approval state; a readable "what changed since baseline X" report; and variants. Variants could be modelled lightly (an attribute or tag per item plus a filter in check/export) rather than with branches, which in git diverge and are costly to merge.

### Gaps
- No source compared enterprise configuration management with git directly in a neutral way.

## Q6: Ideas for requimd

### Takeaway
The most valuable ideas that fit requimd's offline, file-based, single-binary constraints are a rule-by-rule quality report (INCOSE/EARS) with a score, per-link-type suspect rules, named baselines with a "changes since baseline" report, a review package in the static site, ReqIF export, duplicate and contradiction hints, and typed parameters. Server-based features (live dashboards, licences, e-signatures with identity management, real-time review) break the constraints.

- Sources per idea are given in the "seen in" column of the table; full citations are in the profiles above.
